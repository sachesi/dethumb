# Desktop entry thumbnail generation

dethumb reads `Icon=` from `.desktop` files and produces a PNG thumbnail at the requested size.

## Lookup chain

The icon name from the desktop entry is resolved through these steps:

1. If it is an absolute path to a readable, non-symlink file with a supported extension, use it directly. On Unix, the file must be world-readable (mode bits `0o444`).
2. Look up the name in the current icon theme (from `gsettings get org.gnome.desktop.interface icon-theme`, falls back to `hicolor`).
3. Try the theme fallbacks: Adwaita, then Papirus.

Candidate names are generated by adding case variants and file-stem forms to catch common naming patterns (e.g. `MyIcon.png` → tries `MyIcon.png`, `myicon.png`, `MyIcon`, `myicon`).

## Rendering

### SVG

SVG icons are parsed with `resvg/usvg` and rasterized with `tiny-skia`. The icon is scaled to fit the requested size while preserving aspect ratio, then centered on a square canvas.

### Raster (PNG / JPEG)

Decoded with the `image` crate, resized with a triangle filter, and centered on a square canvas.

## Output path safety

Output paths containing `..` components are rejected. The thumbnailer protocol passes output filenames derived from the input URI, so this prevents writing outside the thumbnail cache directory.

## Fallback

If thumbnail generation fails for any reason, a generic icon (`application-x-generic` from the Adwaita theme) is rendered as a fallback. Non-thumbnailable errors (unsupported extension on a PE file) exit cleanly without a fallback so the file manager can try another thumbnailer.
